# Bizimii Marketplace UI/UX Redesign

Redesign the existing **Bizimii (bizimii.com)** frontend into a polished, trustworthy, market-validated freelance marketplace.

Bizimii is a Nigerian freelance marketplace connecting clients with skilled freelancers. The current product already has functionality and routes. Your job is primarily to **redesign and improve the UI/UX**, not rebuild the application or unnecessarily change existing business logic.

## Core Objective

Make Bizimii feel like a mature marketplace in the same product category as Fiverr, Upwork, and Freelancer.

Study and borrow their proven UX principles:

- strong marketplace search
- clear navigation
- information-dense but readable layouts
- strong freelancer identity
- obvious trust/reputation signals
- standardized cards
- clear pricing/budget information
- strong CTAs
- excellent filtering
- predictable marketplace interactions
- clear client/freelancer workflows

Do NOT directly clone any platform's visual design.

Bizimii should feel like an established product with its own identity.

---

# 1. Design Direction

The UI should feel:

- Professional
- Trustworthy
- Modern
- Marketplace-first
- Clean
- Fast
- Mature
- Slightly dense rather than excessively spacious

Avoid the generic "AI-generated SaaS dashboard" aesthetic.

Do NOT overuse:

- huge rounded cards
- excessive gradients
- glassmorphism
- giant headings
- excessive whitespace
- floating dashboard widgets
- random shadows
- excessive animations
- pill-shaped everything

Use conventional marketplace UI patterns when they are better.

### Brand

Primary brand color:

`#EA580C`

Use orange strategically for:

- primary CTAs
- active states
- important highlights
- links where appropriate
- selected filters
- brand accents

Do NOT flood the interface with orange.

The majority of the interface should use neutral whites, grays and near-black typography so the orange remains meaningful.

# 16. Existing Application

Before modifying code:

1. Inspect the current project structure.
2. Identify the framework and component architecture.
3. Identify existing reusable components.
4. Identify current routes.
5. Identify existing backend/API/Supabase integrations.
6. Identify authentication and authorization logic.
7. Identify existing responsive behavior.

Preserve working functionality.

Do NOT:

- replace the existing stack unnecessarily
- rewrite backend logic
- modify database schemas without a real requirement
- break Supabase integrations
- remove working features
- invent fake backend functionality

Refactor frontend architecture where necessary.

---

# 18. Marketplace Principle

At every design decision ask:

"Would this help someone decide who to hire, what job to apply for, whether they can trust the other person, or what action they should take next?"

If not, question whether the UI element needs to exist.

Prioritize:

Discovery → Evaluation → Trust → Action → Transaction

over decoration.

---

# 19. Implementation Strategy

Do not redesign everything blindly in one pass.

First:

Audit the current UI.

Then establish:

Typography
Colors
Spacing
Buttons
Inputs
Cards
Navigation
Marketplace layout primitives

Then progressively redesign:

1. Global navigation
2. Job discovery
3. Job details
4. Freelancer discovery
5. Freelancer profiles
6. Dashboard
7. Proposals
8. Messages
9. Workspace
10. Secondary pages

Reuse components aggressively.

After each major page, verify:

Desktop
Tablet
Mobile
Loading states
Empty states
Existing functionality

The finished product should look like a credible freelance marketplace that could realistically compete in the Nigerian market—not a template, hackathon project, or generic SaaS dashboard.
